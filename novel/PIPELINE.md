# 집필 파이프라인

이 소설은 다중 에이전트 파이프라인으로 집필된다. 모든 에이전트는 작업 전 반드시 아래 파일을 읽는다.

## 디렉터리
- `novel/bible/00_개요.md` : 제목, 로그라인, 문체 가이드, 양산형 공식
- `novel/bible/01_세계관.md` : 세계관, 지리, 세력, 역사
- `novel/bible/02_인물.md` : 인물 프로필 + **말투 규칙 + 예시 대사**
- `novel/bible/03_관계.md` : 인물 관계도 및 변화 추적
- `novel/bible/04_과거_전생.md` : 회귀 전(1회차) 연표. 주인공이 아는 미래.
- `novel/bible/05_힘체계.md` : 마나/검기/등급/스킬 체계
- `novel/bible/06_연표.md` : 회귀 후(2회차) 화별 사건 기록. **매 화 집필 완료 후 갱신.**
- `novel/bible/07_상태표.md` : 현재 각 인물의 위치/상태/소지품/알고 있는 정보. **매 화 갱신.**
- `novel/plan/00_전체구성.md` : 전체 아크 구성, 화별 한 줄 요약
- `novel/plan/epNNN.md` : N화 장면 계획
- `novel/episodes/epNNN.md` : N화 본문
- `novel/logs/epNNN_*.md` : 검증/검토 리포트

## 역할
1. **계획 에이전트**: 바이블 + 전체구성 + 연표 + 직전 화 본문을 읽고 `plan/epNNN.md` 작성.
2. **집필 에이전트**: 계획 + 바이블 + 직전 화를 읽고 `episodes/epNNN.md` 작성. 분량 6,000~8,000자(공백 포함).
3. **검증 에이전트 (5종, 병렬)**: 사건 / 말투 / 관계 / 설정 / 과거. 각각 `logs/epNNN_<종류>.md`에 리포트.
4. **수정 에이전트**: 검증 지적 사항을 본문에 반영.
5. **검토 에이전트**: 독자 관점 품질 검토. PASS / REWRITE / REPLAN 판정.
6. **기록 에이전트**: PASS 후 연표/상태표/관계/인물 파일 갱신.

## 본문 형식
- 첫 줄: `# 제N화. 소제목`
- 1인칭 주인공 시점 기본. 필요 시 `* * *` 구분 후 3인칭 타인 시점 삽입.
- 웹소설 문체: 짧은 문단, 잦은 줄바꿈, 대사 앞뒤 공백 줄, 내면 독백은 작은따옴표 `'…'`.
- 화 끝은 반드시 다음 화를 보고 싶게 만드는 절단(클리프행어).
