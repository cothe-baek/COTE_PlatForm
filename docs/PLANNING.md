# 코딩테스트 준비 플랫폼 기획안

- 문서 버전: v0.1 (초안)
- 작성일: 2026-09-25
- 상태: 검토 대기

---

## 1. 개요

### 1.1 한 줄 정의
취업·이직을 위한 코딩테스트를 **"문제 풀이 → 오답 복습 → 모의고사"** 의 학습 루프로 준비하게 해주는 웹 플랫폼.

### 1.2 배경 및 문제 정의
- 기존 서비스(백준, 프로그래머스, LeetCode 등)는 **문제 은행**으로서는 훌륭하지만, "무엇을 어떤 순서로 풀어야 하는지", "틀린 문제를 언제 다시 풀어야 하는지"는 사용자가 알아서 관리해야 한다.
- 실제 코딩테스트는 **제한 시간 안에 여러 문제**를 푸는 형식인데, 평소 연습은 문제 하나씩 시간 제한 없이 푸는 경우가 대부분이라 실전 감각이 부족하다.
- 틀린 문제를 노션·스프레드시트에 따로 정리하는 사용자가 많다. 이 "오답노트"가 플랫폼 밖에 흩어져 있어 복습이 잘 이루어지지 않는다.

### 1.3 핵심 가치 제안
| 문제 | 우리의 해결 방식 |
|---|---|
| 뭘 풀어야 할지 모르겠다 | 유형별 **학습 로드맵**과 실력 기반 문제 추천 |
| 틀린 문제를 다시 안 본다 | **자동 오답노트** + 간격 반복(Spaced Repetition) 복습 알림 |
| 실전 감각이 없다 | 기업 형식을 본뜬 **타이머형 모의 코딩테스트** |
| 왜 틀렸는지 모르겠다 | AI 기반 **힌트 / 코드 리뷰 / 복잡도 분석** |

## 2. 목표와 성공 지표

### 2.1 목표
1. (MVP) 사용자가 문제를 풀고 채점 결과를 받고, 틀린 문제가 오답노트에 자동 적재되는 학습 루프를 완성한다.
2. (2차) 모의 코딩테스트와 학습 로드맵으로 "준비 계획"까지 플랫폼 안에서 끝낼 수 있게 한다.
3. (3차) AI 코드 리뷰와 스터디 기능으로 리텐션을 높인다.

### 2.2 핵심 지표 (KPI)
| 지표 | 정의 | MVP 목표 |
|---|---|---|
| 주간 활성 사용자(WAU) | 주 1회 이상 제출한 사용자 | 100명 |
| 주간 풀이 수 | 사용자당 주간 제출 문제 수 | 5문제 |
| 오답 복습률 | 오답노트에 쌓인 문제 중 7일 내 재도전 비율 | 30% |
| 4주 리텐션 | 가입 후 4주차에 활동한 비율 | 20% |
| 채점 지연 | 제출 후 결과까지 p95 시간 | 5초 이내 |

## 3. 타깃 사용자

### 3.1 주요 페르소나
**① 취준생 지민 (24, 컴공 4학년)**
- 하반기 공채를 앞두고 3개월 집중 준비. 알고리즘 기초는 있지만 DP·그래프에 약함.
- 니즈: "어떤 유형이 부족한지 알고, 그 유형을 집중 훈련하고 싶다."

**② 이직 준비 개발자 현우 (29, 3년차 백엔드)**
- 퇴근 후 하루 1시간. 오래 안 풀어서 감이 떨어짐. 실전 형식 연습이 필요.
- 니즈: "짧은 시간에 효율적으로, 실제 시험처럼 연습하고 싶다."

**③ 비전공 부트캠프 수료생 서연 (27)**
- 기초 자료구조부터 체계적으로. 혼자 하면 포기하기 쉬워서 스터디를 원함.
- 니즈: "순서대로 따라가면 되는 커리큘럼과 같이 할 사람."

### 3.2 비타깃 (초기 범위 제외)
- 알고리즘 대회(ICPC, Codeforces) 상위권 사용자
- 기업 채용 담당자용 시험 출제 기능(B2B)

## 4. 경쟁 서비스 분석

| 서비스 | 강점 | 약점 (우리의 기회) |
|---|---|---|
| 백준 (BOJ) | 방대한 문제 수, 커뮤니티 | 학습 경로 없음, 오답 관리 없음, UI 노후 |
| solved.ac | 티어·태그 기반 실력 지표 | 백준 의존, 자체 풀이 환경 없음 |
| 프로그래머스 | 기업 모의고사, 국내 채용 연계 | 문제 수 제한, 복습 기능 없음 |
| LeetCode | 기업별 문제 태그, 프리미엄 | 영어, 국내 기업 형식과 다름 |
| 코드트리 | 커리큘럼형 학습 | 유료 장벽, 모의고사·오답 루프 약함 |

**차별점:** 문제 은행 경쟁이 아니라 **"준비 과정 관리"** 에 집중한다. 로드맵 → 풀이 → 오답 복습 → 모의고사가 한 흐름으로 이어지는 것이 핵심.

## 5. 핵심 기능

### 5.1 기능 우선순위
| 단계 | 기능 | 우선순위 |
|---|---|---|
| MVP | 회원가입/로그인, 문제 목록·상세, 코드 에디터, 채점, 제출 이력, 자동 오답노트, 기본 대시보드 | P0 |
| 2차 | 학습 로드맵, 유형별 추천, 모의 코딩테스트, 복습 알림(간격 반복), 통계 상세 | P1 |
| 3차 | AI 힌트·코드 리뷰, 스터디 그룹, 랭킹/배지, 다른 사람 풀이 보기 | P2 |

### 5.2 MVP 기능 상세

**(1) 문제 풀이**
- 문제 목록: 난이도(1~5), 유형 태그(구현, DP, BFS/DFS, 그리디, 이분탐색, …), 풀이 상태 필터
- 문제 상세: 지문, 입출력 예시, 제약 조건, 시간/메모리 제한
- 코드 에디터: Monaco 기반, 언어 선택(Python, Java, C++, JavaScript 우선), 자동 저장
- 예제 실행("테스트")과 최종 제출 분리

**(2) 채점 시스템**
- 제출 → 큐 → 격리된 실행 환경(컨테이너)에서 테스트케이스 실행 → 결과 저장
- 결과 종류: 정답(AC), 오답(WA), 시간 초과(TLE), 메모리 초과(MLE), 런타임 에러(RE), 컴파일 에러(CE)
- 테스트케이스 단위 통과 여부와 실행 시간·메모리 표시

**(3) 자동 오답노트**
- AC가 아닌 제출이 생기면 해당 문제를 오답노트에 자동 등록
- 사용자가 메모(틀린 이유, 핵심 아이디어) 작성 가능
- 재도전하여 AC 시 "복습 완료"로 상태 전환. 완전 삭제 대신 이력 유지

**(4) 대시보드**
- 오늘 푼 문제 수, 연속 풀이 일수(streak)
- 유형별 정답률 레이더 차트
- 오답노트 미복습 개수

### 5.3 2차 기능 상세

**(5) 학습 로드맵**
- 트랙 예시: "기초 자료구조 4주", "코테 필수 알고리즘 8주", "삼성 SW 역량테스트 대비"
- 각 트랙은 단계(step)와 문제 세트로 구성. 단계 완료 조건(예: 5문제 중 4문제 AC)
- 진행률 표시, 이어서 풀기

**(6) 모의 코딩테스트**
- 형식 프리셋: 문제 수 × 제한 시간 (예: 3문제/120분, 4문제/180분)
- 시작 후 타이머 진행, 문제 간 이동 가능, 시간 종료 시 자동 제출
- 종료 후 리포트: 문제별 소요 시간, 정답 여부, 예상 통과 커트라인 비교

**(7) 복습 알림(간격 반복)**
- 오답 문제에 대해 1일 → 3일 → 7일 → 14일 간격으로 재도전 권장
- 대시보드의 "오늘의 복습" 위젯과 이메일/푸시 알림

### 5.4 3차 기능 상세

**(8) AI 힌트 / 코드 리뷰**
- 단계별 힌트(접근 방향 → 자료구조 → 의사코드)로 정답 유출 없이 지원
- 제출 코드 리뷰: 시간복잡도 분석, 엣지케이스 지적, 더 나은 접근 제안
- 힌트 사용 여부를 통계에 반영(힌트 없이 푼 문제 vs 힌트 사용)

**(9) 스터디 그룹**
- 그룹 생성, 주간 문제 세트 배정, 멤버 진행률 보드
- 그룹 내 풀이 공유 및 코멘트

**(10) 랭킹·배지**
- 주간 풀이 수·streak 기반 리더보드
- "DP 10문제 달성" 같은 유형 배지

## 8. 기술 아키텍처

### 8.1 구성도
```
[Browser: Next.js + Monaco]
        │ HTTPS / REST + WebSocket(채점 결과 푸시)
        ▼
[API Server: NestJS 또는 Spring Boot]
   │            │              │
   ▼            ▼              ▼
[PostgreSQL] [Redis]      [Message Queue (Redis Streams / RabbitMQ)]
                                │
                                ▼
                       [Judge Worker × N]
                       각 제출을 Docker 컨테이너에서 격리 실행
                       (CPU/메모리/시간 제한, 네트워크 차단)
                                │
                                ▼
                         [Object Storage: 테스트케이스, 제출 코드]
```

### 8.2 기술 스택 (제안)
| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트엔드 | Next.js (React, TypeScript), Tailwind, Monaco Editor | SSR·SEO, 에디터 생태계 |
| 백엔드 API | NestJS (TypeScript) | 프론트와 언어 통일, 모듈 구조 |
| DB | PostgreSQL | 관계형 데이터(문제·제출·사용자), JSONB로 유연성 |
| 캐시·큐 | Redis | 세션, 랭킹(ZSET), 채점 큐 |
| 채점 워커 | Node/Go 워커 + Docker (또는 isolate/nsjail) | 격리 실행, 수평 확장 |
| 인증 | 이메일/비밀번호 + OAuth(Google, GitHub) | 개발자 타깃 |
| AI | LLM API (힌트·코드리뷰) | 3차 기능 |
| 인프라 | Docker Compose(개발) → AWS ECS/EKS 또는 단일 VM(초기) | 단계적 확장 |
| 모니터링 | Sentry, Prometheus/Grafana | 채점 지연·에러 추적 |

> 팀 숙련도에 따라 백엔드는 Spring Boot(Java)로 대체 가능. 채점 워커는 언어와 무관하게 컨테이너 격리만 보장하면 된다.

### 8.3 채점 시스템 설계 (핵심)
1. API가 제출을 `submissions` 테이블에 `PENDING`으로 저장하고 큐에 `submission_id`를 발행
2. 워커가 큐에서 꺼내 언어별 이미지로 컨테이너 실행
   - 자원 제한: CPU 1코어, 메모리 문제별 설정(기본 256MB), 벽시계 시간 제한
   - 보안: 네트워크 비활성화, 읽기 전용 파일시스템, 비루트 사용자, seccomp 프로파일
3. 테스트케이스를 순차(또는 병렬) 실행하며 stdout을 기대 출력과 비교(공백 정규화)
4. 결과를 DB에 반영하고 WebSocket으로 사용자에게 즉시 전달
5. 첫 실패 시 조기 종료(제출), 예제 실행 시에는 전체 출력 표시

**언어 지원 우선순위:** Python 3 → Java 17 → C++17 → JavaScript(Node) → Kotlin, Go

## 10. 개발 로드맵

| 마일스톤 | 기간(안) | 산출물 |
|---|---|---|
| M0 기획·설계 | 1주 | 기획안 확정, 와이어프레임, ERD, API 명세 |
| M1 기반 구축 | 2주 | 프로젝트 셋업, 인증, 문제 CRUD(관리자), 문제 목록·상세 |
| M2 채점 시스템 | 3주 | 큐·워커·컨테이너 격리, 4개 언어, 결과 실시간 표시 |
| M3 학습 루프 | 2주 | 오답노트 자동 등록, 제출 이력, 대시보드 → **MVP 배포** |
| M4 로드맵·모의고사 | 3주 | 로드맵 3개 트랙, 모의고사 프리셋·리포트, 복습 알림 |
| M5 AI·커뮤니티 | 3주 | AI 힌트·리뷰, 스터디 그룹, 랭킹 |

- MVP까지 약 8주, 전체 약 14주 기준. 1인 개발이면 M2에서 격리 실행을 가장 먼저 검증할 것.
- 초기 문제 세트: 유형별 10문제 × 8유형 = 약 80문제를 자체 제작(라이선스 이슈 회피).

## 11. 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|

| 채점 부하 폭주(모의고사 동시 종료) | 지연 | 큐 기반 비동기 처리, 워커 오토스케일, 제출 속도 제한 |

| 문제 저작권 | 법적 리스크 | 타 플랫폼 문제 무단 복제 금지, 출처·라이선스 명시 |
| AI 힌트가 정답을 유출 | 학습 효과 저하 | 단계별 힌트 프롬프트 설계, 정답 코드 직접 출력 금지 규칙 |
| 리텐션 저조 | 성장 정체 | 복습 알림, streak, 스터디 등 습관 형성 장치 우선 배치 |
